# 单章生产实验边界

本模块验证已定盘输入的逐章生产，不执行创意发散或完整自动导演。复用工作台的 Prisma、Provider、Prompt Runner、模型用量与提示词管理。单独的实验记录是最小闭环的权威稿件与状态；不调用自动导演，也不把它的降级完成策略当作本实验的验收标准。

创建实验时同时创建小说身份，仅用于作品范围的提示词、slots 和用量归属；正文、修复历史与状态留在 FactoryBook，不回填传统 Chapter／角色资产表。因此从 `/factory` 执行、查看和恢复，不能同时从传统工作台继续这份实验。若今后并入正式连载主链，必须将此入口转换为统一 ChapterRuntimeCoordinator 的适配器，并迁移状态与连续性证据，不能维持两条正式生产主链。

`domain/` 只校验结构化审校结果、应用局部补丁与计算提交。`application/` 按保存步骤调度。`infrastructure/` 通过 Prompt Runner 调用已注册资产，并用数据库版本比较保证保存完整实验快照。`http/` 提供输入校验与安全错误，界面不承担事实判断。

定稿正文和故事状态存于同一个数据库行，`revision` 条件更新是原子边界。审校提取的变化必须有原文证据、正确 before 值、普通剧情变化类别；锁定键、重大新设定和未通过检查不能提交。语义判断仍依赖审校模型，不能把数据库校验理解为小说质量保证。

一次实验至多十个导入目标，连续按钮至多推进三章。角色位置、伤势、物品、关系、知识和伏笔可按状态键记录；不建立大型检索系统。完成本章提交后生成下一章小剧本和默认正文指令；交接失败只重试交接，不重新写正文或重复应用状态。

暂停只改变任务状态。已发出的调用返回后仍保存产物，保存时保留暂停状态，再停止下一次调用。`executionActive` 是读取时的租约投影，不进入永久故事状态。进程中断或无执行者的 running 会投影成暂停；显式恢复才继续。

本机单用户模式以数据库租约排除重复执行，心跳保持租约。回写要求 owner 与有效期匹配，失去租约者不得写入。repair 调用前持久预约两轮额度，网络中断不返还次数；恢复先复审已有正文。局部补丁使用唯一、不重叠的原文锚点，累计触及超过六成正文时拒绝。

模型没有返回 usage 时保持未知，不估算费用或伪造 token。自动 schema 修复和语义重试关闭；故障需要显式恢复，保证模型调用和两轮修复可追溯。生产使用本实验关联小说的提示词范围；导出的下一章指令是官方默认模板，个性化模板应通过提示词管理预览。
