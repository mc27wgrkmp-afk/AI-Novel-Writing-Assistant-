# Gemini 本地网关诊断边界

## 判断可用性的依据

本地端口可连接、`/v1/models` 返回列表、Gemini 首页返回 HTTP 200，都不能证明生成可用。模型列表由网关本地维护；Google 首页可能显示未登录页面，生成接口也可能独立拒绝请求。

必须区分网关进程、代理网络、Google 登录会话与实际生成。只有最小生成请求返回非空正文，才可确认生成恢复。诊断不得发送小说内容、恢复工作流或改写创作数据。

## Gemini-API 适配器边界

`scripts/gemini_gateway/` 负责可选 HanaokaYuzu/Gemini-API 传输；复用固定版本旧网关的 HTTP 请求、工具输出与缓冲 SSE 格式，小说工作流不直接依赖 Python 库。库固定到 `8c5b1dcbf54ecf093551cc20bd25cef438190ba8`，使用独立 Python 3.11+ 环境。升级时必须重新验证内部重试策略与请求协议。

安装并选择新引擎：`bash scripts/setup-gemini.sh --hanaoka`，然后运行 `bash scripts/start-gemini.sh`。安装会私密备份原配置并保存 `gateway_engine=hanaoka`。临时切回可用 `GEMINI_GATEWAY_ENGINE=legacy bash scripts/start-gemini.sh`；同一端口只启动一个引擎。两个引擎共用原有 Cookie 文件、API 地址与节流状态，切换不能解除验证暂停或失败冷却。

客户端在第一次获准生成时初始化，维持同一 HTTP 会话，读取该账号的可用模型和请求参数，拒绝未登录/访客会话。`/v1/models` 只返回本地缓存和明确标注的 Web 路由；首次初始化前不宣称已验证账号可用。生成时先解析账号真实模型，旧 Fast 名称兼容到账号 Fast/Flash 档；不锁定版本、不尝试其他档位作为备用型号。

适配器将 `_generate` 与 `_batch_execute` 的库内重试次数设为零，关闭库的自动后台刷新与额外保活，活动/额度查询最多二十分钟一次。流中断时只读现有会话结果，读取间隔至少六十秒，不重新提交原提示词。对外仍缓冲完整结果后再发送 SSE，保持上游失败返回 HTTP 502；真实逐字流式输出不属于此适配阶段。

已使用的会话每二十分钟尝试一次 Cookie 续期。续期经过与生成相同的锁、间隔、冷却及人工暂停检查，因此不会在暂停时访问 Google，也不会与生成并发。认证、配额、429 或验证异常设置人工恢复标记；续期失败不能自行清除。低频会话维护不保证消除 Google 的上游限制。

Cookie 缓存保留 Google 域、路径与过期属性，放在 `.local-data/gemini-api/` 私密目录内；文件 `0600`、目录 `0700`，不打印库内诊断。缓存按原始会话快照的摘要隔离，用户重新复制并保存 Cookie 后不让旧缓存覆盖新快照。新引擎的安全诊断只读取本地状态，`--generate` 通过实际运行中的网关发送最小测试，不能用旧快照单独访问网页来判断新会话是否有效。

仅支持文本创作与已有工具文本协议，附件请求明确拒绝，不调用旧网关上传通道。涉及系统指令的业务提示词继续由应用组装，适配器不自动创建或修改用户 Gems。

该适配器使用默认 Google 账号会话；配置了非默认 `auth_user` 时拒绝初始化，避免悄悄切到其他账号。需要其他账号时先使用独立的默认账号浏览器会话更新本地 Cookie，不能只忽略账户路径配置。

## 请求频率与暂停边界

所有文本生成共享一个串行通道。回复完整结束后至少等待 120 秒，启动时也等待完整间隔；较慢的用户配置会保留。间隔从完成计算，不能仅从请求开始计算，否则较长生成完成后会立刻发下一个请求。规划、正文、审校、修复与测试都遵守这个通道。

启动脚本将网关内部 `retry_attempts` 固定为 1。外层排队并不能限制一次调用内部的快速重试，所以两层都必须约束。普通异常进入至少 900 秒冷却；冷却中的后续调用直接失败，不访问 Google。

上游 401、403、429、验证 HTML、`/sorry/`、验证码提示或 `BardErrorInfo` 拒绝会设置持久化人工恢复标记。它是保守的安全暂停，并不据此推断 Google 的唯一拒绝原因。该标记不随冷却到期或重启清除，防止后台任务重新触发同一限制。

用户处理网页验证、确认网页版可以发送消息，并按需更新网关会话后，才显式运行：

```sh
.local/gemini-venv/bin/python scripts/gemini_throttle.py --resume-after-verification
```

随后重启网关。此命令只清除人工恢复标记，保留两分钟间隔及尚未到期的失败冷却，不发送请求，也不处理验证。状态文件仅保存时间与暂停标记，不保存提示词或凭据。降低频率不能保证上游永远不要求验证；实际出现验证时必须保持暂停。

## 安全诊断方法

在项目根目录运行：

```sh
.local/gemini-venv/bin/python scripts/diagnose-gemini.py
```

脚本读取网关配置，通过相同代理、Cookie 和账户路径检查 Google 页面。只输出状态，不打印 Cookie、认证令牌、账户资料、完整重定向链接或页面正文。需要验证生成时添加 `--generate`，它只发送 `Reply only OK.`，并输出是否收到内容。

不能只用 `lsof` 判断代理是否运行：以其他权限运行的核心进程可能不在输出中。用明确指定代理的 HTTP 请求验证代理，避免直连与系统代理出口混淆。

## 常见失败与处理

- 页面有 `Sign in` 按钮且缺少 `SNlM0e`：现有 Cookie 没有得到已登录页面。Cookie 文件存在不代表会话有效。请用户先在使用同一代理出口的 Gemini 网页完成登录并发送一条测试消息，然后按网关的会话配置流程更新 Cookie 和令牌。
- 重定向至 Google `/sorry/`：上游要求验证或限制该出口。保留错误状态，请用户在网页确认具体提示；不要自动完成验证码或将空响应视为成功。
- `BardErrorInfo [1060]`：Google 拒绝了生成请求。该错误本身不能唯一证明 Cookie、地区、IP 或协议中的哪一个因素有问题。结合登录页面状态、代理出口与网页真实发消息结果继续判断，不能只反复重启网关。
- 冷却提示：网关上游失败后按配置进入冷却。诊断应等待现有冷却，不清空节流状态或密集重试。

## 网页能生成而网关失败

浏览器当前会话与网关磁盘快照是两份独立状态。若用户确认同机 Gemini 网页能发送消息，而诊断中的现有 Cookie 得到未登录页面，应先修复网关会话快照；不能据此判断用户账户不可用。

刷新时从用户当前已登录的 Gemini 页面读取真实请求的 Cookie、`at` 表单字段或页面的 `SNlM0e`，同时确认使用的 Google 账户路径。Cookie 放入配置指定的本地 `cookie_file`；`at` 放入网关配置的 `xsrf_token`，非默认账户同步 `auth_user`。这些值只在本机私密文件内处理，不贴到聊天、日志、截图或提交中。更新前保存权限为 `0600` 的私密备份，更新后保持相同权限并重启网关，因为配置只在启动时读取。再次运行安全诊断，并用最小生成成功确认恢复；若仍返回 1060，继续比对请求协议和出口，不能宣称已恢复。

macOS 可在 Gemini 网页的开发者工具「网络」中查看刚发消息的 `StreamGenerate` 请求，只复制请求标头的 Cookie 单行值（允许带 `Cookie:` 前缀），再在项目根目录运行：

Safari 操作：打开已登录的 Gemini 标签页，按 `Option + Command + I` 打开网页检查器；若没有开发菜单，在 Safari「设置 → 高级」启用网页开发者功能。选择「网络 / Network」，保持检查器打开后发送一句测试消息，在请求列表查找 `StreamGenerate`。打开请求的「标头 / Headers → 请求标头 / Request Headers」，对 `Cookie` 使用「复制值 / Copy Value」，只复制这一项到本机剪贴板。不要复制整条请求、上传截图或将值发送到聊天。

```sh
.local/gemini-venv/bin/python scripts/refresh-gemini-session.py --clipboard
```

工具只在显式使用 `--clipboard` 时读取剪贴板。先用当前代理与账户路径验证已登录页面，并提取其会话令牌、构建号；验证失败不会改写配置。验证通过后在 `.local-data/gemini-session-backups/` 保存私密备份，原子替换各私密文件，只更新 Cookie、SAPISID、令牌、构建号及 Cookie 文件路径，保留其他配置。它不发送生成请求、不自动登录、不处理验证码、不修改浏览器会话。完成后用 `bash scripts/start-gemini.sh` 重新启动网关（若端口已占用，先正常停止原来的网关进程），再执行最小生成检测。

带凭据请求只能将 Cookie 发送给原 HTTPS 来源。诊断脚本在跨来源重定向时剥离 Cookie 与 Authorization；刷新脚本直接拒绝跨来源重定向，避免登录或验证页面接收到网关凭据。

## 维护边界

补丁与本地诊断工具位于 `scripts/`。`.local/` 为安装后的网关，`.local-data/` 保存私密会话与运行状态；不要将这些目录中的 Cookie、配置秘密、请求正文或数据库纳入提交。

限流器必须在网关配置加载后初始化：网关模块导入时配置仍为默认值，此时不能固定状态文件路径。首次请求使用已加载配置，在初始化锁下创建唯一限流器。离线回归应覆盖配置后加载、拒绝状态落盘及重启后不再调用上游，不能只测试独立限流器。

## 响应 Cookie 更新

登录页验证和生成回复可能返回新的 Set-Cookie。只保存用户复制的请求头会遗漏响应更新；刷新工具应合并已接受的响应 Cookie，并同步 SAPISID。网关在读取生成回复前保存响应更新，更新前保留私密副本，原子替换后的文件权限为 0600。只接受原 HTTPS Gemini 来源及标准 Cookie 域策略允许的更新，不输出值。这能补齐客户端会话维护，不能保证会话永不失效，也不能据此将 1060 全部归因于 Cookie。

暂停与冷却作用于整个网关，不区分 Gemini 型号。检测确实发送到新型号但网关拒绝时，应展示网关级原因，不能把它解释为模型选择未生效。连通检测遇到明确暂停、冷却或 BardErrorInfo 就停止协议及格式探测；结构化调用也停止传输重试和同厂商备用型号尝试。其他厂商的显式备用路由仍按原设置处理。检测不通过时快速配置保留既有配置。

## Gemini 3.8 模型选项

官方 API 模型代码为 `gemini-3.8-flash`，参见 [Google 模型文档](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash)。工作台内置 Gemini 配置对新配置推荐此模型，已保存模型不自动迁移。本地网关将同名选项映射到 Web Fast 档（mode=1），不宣称能锁定实际 3.8 版本；已有 3.7/3.6 等 Fast 名称也属于同类路由。模型列表成功返回只证明选项被注册，不代表登录会话有效或生成成功。新增选项不清除暂停与冷却。
