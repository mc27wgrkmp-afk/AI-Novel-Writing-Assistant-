# 本地三平台整合边界

## 背景与决定

Biz Novel Studio 是统一应用。WebFictionLab 提供研究样本及可追溯研究，Scriptor 提供文件书仓与作者批准流程。整合应共享主平台作品、章节、知识文档与模型配置，不创建第二套权威正文。

## 当前规则

- 研究样本只创建知识文档，不创建作者小说；来源章序与 UUID 独立保留，不能靠同名判断同章。
- 原始正文和候选事实分开，原文件与提取后正文分别保存哈希。旧审核是历史资料，不产生新批准。
- 版本用既有 NovelSnapshot，专用工件使用 `unified_*` triggerType，不进入普通整书恢复，也不受普通章节40版裁剪影响。
- 作品的手写/AI策略与原创/续写独立。策略切换不启动旧工作流；统一入口单章起草输出草稿，旧自动批量链仍关闭。
- 模型输出、审读通过、作者批准、正式事实提交是不同动作。批准绑定具体正文、上下文、摘要与事实；旧批准和被取代事实留历史，有效账本只读当前版本。
- 人物、正式书级契约、世界、卷章计划和前文均参与上下文哈希，不能仅校验正文。
- 同源导入幂等；源哈希变化返回冲突，不静默覆盖目标作者编辑。
- 备份数据库使用 SQLite backup 一致快照，书仓逐文件校验。主库/旧库保留，新工作区使用独立数据库和端口。
- 本地启动器禁止导入前旧任务的后台自动恢复；新平台创建的导演任务由受安装基准时间约束的执行器正常领取。手动暂停和等待审核状态不能被清除。手动按钮继续走现有模型配置。

## 故障排查

- 原稿字数高于阅读器：检查旧文件是否附有候选事实，不能将附录当成小说正文。
- 批准立即失效：检查当前章批准是否错误参与自己的上下文哈希；当前正文与该章批准单独绑定，前章正式事实才进入后章上下文。
- 事实重现或互相矛盾：检查有效批准指针及 superseded 过滤，不删除原批准证据来掩盖变更。
- macOS 原生模块无法载入：使用项目已有官方 Node，避免带库加载隔离的应用内 Node；不通过改签名或关闭系统保护解决。

## 新建导演任务停在初始进度

若界面显示运行中，但命令仍为 queued、attempt=0、startedAt为空，先检查执行器是否启动，不应先重建任务或归因于模型超时。统一启动的历史恢复开关与新任务执行职责应分开；DirectorTaskQueue和租约领取、过期扫描同时使用taskCreatedAfter，避免只在界面限制旧任务。安装基准时间持久化于AppSetting，兼容首批导入时点，重启不重置。
